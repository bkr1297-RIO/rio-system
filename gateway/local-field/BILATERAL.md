# Local Field bilateral profile v0.1

Candidate bounded runtime contract; no merge, deployment or constitutional promotion.

Root-signed field definitions pin `bilateral_profile: local-field-bilateral-v0.1`, an active `return_policy`, and `return_authority_basis` referencing a normal signed Local Field grant. The Return grant independently permits subject B, action `record_return`, target node A, target `return-record`, scope `attributed-record-only`, purpose `local-field-return`. Both endpoints verify the grant with the existing lineage resolver; neither field membership nor a Return signature supplies it.

Source A uses its own receiver key, database and `peers` configuration (`node-id: http://127.0.0.1:PORT`). Peer routes are private development custody configuration, not sender-selected envelope destinations. Only loopback HTTP is supported, redirects refused, response/request bodies bounded, and no whole-machine networking containment is claimed. No replicated/partition authority behavior is claimed.

Signed control records and immutable source transits are bounded to 64 KiB, and field profile configuration is similarly bounded. Native proof expansion uses a distinct 8 MiB Return limit. B conservatively budgets the complete native Return from the actual immutable request, transit, intent, policy and grant closures before admission/effect; sixteen projections plus 64 KiB generated overhead must fit. No pre-effect receipt is fabricated. Unsupported non-returnable closures are refused before consequence, and actual emitted size is checked against the persisted budget. This preserves the full 4096-byte artifact profile, including worst-case JSON-escaped content. Current node lookup rechecks signed enrollment validity as well as revocation; expiration is not continuing membership authority.

`POST /dispatch` on A receives its signed version `0.1`, `single-use` passage. A's current grant and canonical RIO policy produce a durable signed egress decision before the owned network emission. `POST /receive` on B verifies the immutable passage transit; independently resolves B's current grant/policy, records ingress, then records a separate current execution-authority result and Sentinel fidelity immediately before the existing create-only artifact executor. Direct `/admit` and `/passages` cannot bypass controlled transit in this profile. Older profiles retain their explicitly narrower predecessor APIs.

The native five-hash receipt, occurrence/readback, Return and full-chain signed Return transit are preserved. B's Return egress and A's `POST /returns` admission separately check current Return standing and RIO. A records `ADMITTED_AS_ATTRIBUTED_RECORD`, `UNESTABLISHED` truth, `ATTRIBUTED_CLAIM` observation, `NOT_ADMITTED` evidence, `UNSETTLED` settlement, `RETURNED_WITH_RESIDUE` completion. These statuses grant no consequential permission. Records preserve attributable claims, not truth. Model-originated requests still require a separately typed non-authoritative candidate and actual scoped grants.

Source and target transport identity are bound separately from the subject field. This bounded profile requires subject == source_node; third-party carrier/subject relations are refused rather than guessed. Immutable signed envelope hashes bind action, target, scope, purpose, conditions, dependencies, payload, expiry, nonce, correlation, required Return route and optional non-authoritative lineage. Unknown versions, replay modes and envelope extensions are refused. Enrollment, source identity, integrity, lineage and correlation are not authority.

Pending dispatch restart never retransmits, regenerates permission or infers non-occurrence. It records `UNSETTLED` residue. Successful completed lineage and all node/grant/Return identities reconstruct from the existing SQLite store/native ledger. Keys remain endpoint-local. All services run in a development trust domain; this is interface/custody separation, not OS-level isolation from an administrator.

Run from gateway: `npm run test:local-field`. Bilateral process acceptance is supplied by the build verification driver, separately from production runtime imports.
