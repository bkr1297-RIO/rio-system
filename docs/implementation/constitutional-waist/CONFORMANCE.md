# Constitutional Waist + Active HOLD — candidate conformance

The implemented minimum is: difference remains addressable, transformation remains answerable, and progression does not manufacture promotion. This is an opt-in LocalField conformance profile, not a new authority runtime.

| Required distinction | Operative enforcement / evidence |
|---|---|
| Candidate ≠ Admissible | Signed native formation is bound through canonical `origin.candidate_id`, not a new wire field. Candidate passage is retained independently of immutable ADMIT/HOLD/DENY records. CCM binding and current native RIO/grant checks determine admission. |
| Admissible ≠ Committed | ADMIT issues no token in this profile. An independently signed root invocation commitment must bind the exact admitted decision and passage hash. |
| Committed ≠ Invoked | A root commitment cannot create an invocation. A fresh original-source signature and exact request must cross `invoke`. |
| Invoked ≠ Attempted | Invocation is durable before the existing descriptor-bound guard commits a native attempt; failures before that guard create no attempt. |
| Attempted ≠ Executed | Native attempt precedes open/create. Executor COMPLETED/FAILED result is recorded separately. |
| Executed ≠ Occurred | Successful create produces no native occurrence account until the separate descriptor read. Removal before readback yields UNKNOWN without rewriting COMPLETED execution. |
| Occurred ≠ Observed | Native occurrence account and identified observation record remain distinct. Observation is supplied only by the receiver's real readback, not by caller-supplied occurrence data. Physical occurrence remains an exterior fact. |
| Observation ≠ Evidence | Observation input cannot be submitted as an Evidence control; no Evidence constructor is introduced. |
| Return ≠ Settlement; Next ≠ Successor | Existing signed Return completes the account. CCM custody remains UNASSESSED/UNSETTLED until its existing independent owners act. HOME and successor mutation are not invoked. |
| Prediction/Capability ≠ Permission/Authority | Uncertainty and obligation metadata, graph participation, execution and Return do not modify the signed field root or widen grants. |
| HOLD ≠ DENY | Both project to actuator 0, while decision IDs, reason, lineage, steps and disposition remain in the native record. DENY is terminal for that immutable candidate. |

The tests cover all twelve requested hostile conditions, along with forged-root signatures, original-source revocation, restart before/after execution, single use, malformed burden contracts, withdrawal, bounded HOLD work and the HTTP convenience endpoint. Raw commands/results and one complete trace are in the Return evidence directory.

PROBE is an implemented non-consequential local inspection of existing CCM standing and native eligibility. RECALIBRATE, REQUEST_SOURCEPOINT, REPAIR_LINEAGE, WAIT and REPLAN record local next-step intents alongside that inspection; they do not claim an external probe, calibration, delivered message or autonomously repaired authority. WITHDRAW prevents further reconsideration of the candidate. Maximum work per candidate is 32 HOLD steps and 16 dispositions. A HOLD step does not create ADMIT; the existing gates are re-evaluated for a distinct decision.

Native policy AUTO_DENY stays DENY. A native unmet approval requirement remains HOLD; this profile does not supply quorum/unanimity or manufacture approval from a single root commitment.

Enforcement boundary: the accepted Linux LocalField API and its descriptor-bound create-only adapter. Automatic `/passages`, projection-operation and bilateral dispatch/receive conveniences cannot dispatch through this profile without the explicit sequence. The accepted specimen uses separate authenticated HTTP calls to the existing CLI process. This does not prove containment of a compromised physical host, private OS filesystem access or every unrelated runtime route.

The final descriptor guard authenticates the stored invocation and checks its lease again after cryptographic work, alongside commitment, formation and grant temporal burdens. Native receipt construction validates each derived stage against native ledger custody, original signatures and exact cross-record bindings. This validation is enabled before CCM replays captured native Returns on restart. Historical signature/custody verification does not depend on a historical request remaining currently unexpired.

An admission retry may return its immutable prior disposition, explicitly labeled HISTORICAL_RECORDED_DECISION, with separate current eligibility. A past ADMIT never substitutes for current execution authority.

No merge, deployment, public publication, canon promotion, authority redesign, UI redesign, autonomous learning or settlement installation is performed by this candidate.
