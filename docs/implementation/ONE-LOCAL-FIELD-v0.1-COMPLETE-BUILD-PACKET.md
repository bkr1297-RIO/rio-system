# 6.5 PASSAGEENVELOPE — EXPLICIT SEMANTIC CONTRACT

`PassageEnvelope` is the transportable constitutional record of a proposed consequential crossing.

It is not itself:

```text
authority
admission
execution permission
execution
occurrence
evidence
settlement
Return
```

If an existing canonical protocol object already provides these semantics, reconcile this contract into that object rather than creating a duplicate `PassageEnvelope` type.

Field names below are semantic names. Existing canonical names win where equivalent.

## 6.5.1 `passage_id`

Stable opaque identifier for this exact proposed passage instance.

Required.

Immutable after constitution.

Must not be reused for a materially different passage.

Identity alone confers no authority.

## 6.5.2 `schema_version`

Identifies the semantic/schema profile used to interpret the envelope.

Required unless canonical protocol provides equivalent unambiguous versioning outside the envelope.

Unknown versions must not be silently interpreted as known versions.

Optional canonical equivalent:

```text

```

## 6.5.3 `field_id`

Identifies the constituted Local Field context.

Required for Local Field inter-node passage.

Field membership does not confer passage authority.

## 6.5.4 `source_node_id`

Identifies the transmitting/constituting node.

Required.

This is a claim until verified against the applicable identity/integrity mechanism.

ClaimedSource ≠ VerifiedSource.

## 6.5.5 `subject_id`

Identifies the participant whose standing is relied upon.

Required for consequential passage.

The subject may differ from the transporting node.

TransportingNode ≠ AuthoritySubject.

## 6.5.6 `target_node_id`

Identifies intended receiving node/execution domain.

Required for bilateral inter-node passage.

A passage for B must not silently execute at C.

## 6.5.7 `action`

Canonical action identifier plus action-specific parameters where applicable.

Required.

Must be specific enough for authority resolution, RIO, current execution authority, Sentinel fidelity and receipt reconstruction.

## 6.5.8 `target`

Typed target-resource reference.

Required where the action has a target.

Must bind the target strongly enough to detect substitution.

Authorized(Target_X) ≠ Authorized(Target_Y) unless authority explicitly covers both.

## 6.5.9 `purpose`

Bounded purpose identifier/structured purpose claim.

Required when authority/governance is purpose-bound.

## 6.5.10 `scope`


# 7. BILATERAL CONSTITUTIONAL PASSAGE

Local Field inter-node passage is bilateral.

A consequential passage from Node A to Node B crosses independently governed participant boundaries.

Return crosses boundaries again.

Accepted semantic path:

```text
A
→ CONTROLLED_EGRESS_A
→ PASSAGE_AB
→ INGRESS_B
→ CURRENT_EXECUTION_AUTHORITY_B
→ FIDELITY_B
→ EXECUTION_B
→ OCCURRENCE_B
→ RETURN_EGRESS_B
→ RETURN_BA
→ RETURN_INGRESS_A
→ EVIDENCE / SETTLEMENT STATUS_A
```

Distinct judgments:

```text
Emit_A
Admit_B
AuthorizeExec_B
VerifyFidelity_B
EmitReturn_B
AdmitReturn_A
```

Preserve:

```text
Connectivity ≠ Standing
PermissionToEmit_A ≠ PermissionToAdmit_B
Admission_B ≠ CurrentExecutionAuthority_B
CurrentExecutionAuthority_B ≠ ExecutionFidelity_B
Execution_B ≠ Occurrence_B
Occurrence_B ≠ ReturnReceipt_B
ReturnReceipt_B ≠ Evidence_A
Evidence_A ≠ Settlement_A
```

## 7.1 Controlled egress

Before consequential dispatch through a Local Field-controlled egress surface, evaluate current authority bound to source node, subject, action, target, scope, purpose, payload/integrity, dependencies, conditions, authority basis, expiry and replay state as applicable.

v0.1 enforcement claim:

> Unauthorized consequential dispatch cannot traverse the accepted Local Field-controlled egress path.

Do not claim whole-machine/network egress containment against arbitrary compromised processes/kernel/channels unless actually established.

Runtime Map must name the exact enforcement boundary.

## 7.2 Transmission

Transmission success ≠ ingress admission.

Transport must not manufacture authority, standing, admission, execution permission or settlement.

## 7.3 Independent ingress

Node B treats incoming passage as attributable but untrusted until its own admission rules evaluate sender, subject, request, target, claimed authority, recognized standing, current grant, scope, local constraints and replay/freshness.

AuthorizedEgress_A ≠ AuthorizedIngress_B.

## 7.4 Current execution-authority recheck

Ingress admission does not permanently authorize later execution.

Immediately before execution establish that authority remains current under revocation, expiry, dependency, subject, target, scope, governing-condition and single-use/spent state.

IngressAdmission_B ≠ CurrentExecutionAuthority_B.

## 7.5 Execution fidelity

After current execution authority is established, Sentinel/fidelity verifies that the operation about to execute is the operation admitted and authorized.

CurrentExecutionAuthority_B ≠ ExecutionFidelity_B.

Authority asks: may it still occur?

Fidelity asks: is this the authorized consequence?

Both must pass.

## 7.6 Local execution and custody

Inter-node cooperation must not merely by membership/delivery grant A unrestricted access to B's private keys, corpus, internal memory/storage, unrelated capabilities/authority or implementation state.

Connectivity ≠ CustodyTransfer.

FieldMembership ≠ BlanketDisclosure.

Lawful explicit scoped disclosure remains possible.

## 7.7 Return egress

Node B constructs attributable Return under applicable Return/receipt architecture.

Return disclosure remains bounded by B's authority/custody constraints.

RequestFrom_A ≠ UnlimitedReturnDisclosureBy_B.

## 7.8 Return ingress

Node A treats returned material according to type.

Signature/provenance may establish attribution/integrity/provenance relative to a verification basis; it does not automatically establish truth, evidentiary sufficiency, settlement, permission or successor-state mutation.

SignedBy_B ≠ True.

ReturnReceipt_B ≠ Evidence_A.

Evidence_A ≠ Settlement_A.

## 7.9 Field membership and standing

Node differentiation is weaker than sovereignty.

Nodes may be SourcePoints, delegated projections, services, model runtimes, devices, institutional offices, storage systems or tools.

Field membership does not silently erase, aggregate, transfer or transform participant standing.

Any membership-produced standing change must be explicit, typed, attributable, bounded and reconstructable.

## 7.10 Field authority

The Field is not an implicit sovereign root.

Routing/discovery/registry/identity/authority lookup/telemetry/admission support/receipt transport responsibilities remain bounded by actual grants and constitutional owners.

CoordinationAuthority ≠ ParticipantSovereignty.

FieldMembership ≠ AuthorityAggregation.

"Edge-governed" is an architectural description, not a requirement to duplicate governance engines per node.

Reuse canonical owners.

Required property is semantic bilateralism.

Detect changed target, subject, action, dependency, payload, authority, expiry, revocation and scope as applicable.

```text
→ NON-AUTHORITATIVE ARTIFACT
→ CANDIDATE PASSAGE
→ AUTHORITY
→ RIO

→ EXECUTION
```

ModelOutput ≠ Authority.

Inference ≠ Standing.

Learning ≠ Amendment.

## 8.4 First real consequential adapter

Wire at least one real development-safe adapter through:

```text

→ Node A
→ controlled egress authority
→ PassageEnvelope
→ Node B ingress admission
→ current execution authority

→ receipt/proof

```

A bounded filesystem action is acceptable if it is the best existing owner.

Mocks/simulation alone do not satisfy acceptance.

## 8.5 Receipt and Return

Reuse `rio-receipt-protocol`.

Capture requested, authorized, attempted, occurred, observed/proved, receipt, settlement/disposition if applicable, and Return separately.

Receipt ≠ Truth.

Attribution ≠ Truth.

Receipt ≠ Evidence.

Evidence ≠ Settlement.

Return must correlate to originating passage.

## 8.6 Revocation / freshness

Reject revoked, expired, superseded, stale-dependency, spent/single-use or replayed passages/authority as applicable.

Where ingress and execution separate in time, re-evaluate current execution authority before consequence.

## 8.7 Observability

Expose machine-readable field identity, nodes, capabilities, bindings, authority references, open passages/holds, egress/ingress decisions, current execution-authority results, fidelity, occurrences, receipts, revocations and Return state.

Visibility ≠ Authority.

## 8.8 Security posture

Treat nodes as independently bounded.

Do not assume one unrestricted secret pool/principal/token/trust domain.

Node_A ≠ Node_B.

Design so compromise/validity of A does not automatically confer B's authority within the implemented identity/admission boundary.

Do not claim universal host-compromise containment beyond evidence.

# 16. EXPLICIT GATE CONTRACTS

## CONTRACT A — Architecture and Routing

**Subject:** correct ownership and Engine Loom routing.

**Subject:** one runtime field with at least two differentiated enrolled nodes.

**PASS:** field exists; Node A and Node B enrolled; identities are distinct; runtime reconstructs membership, status, capabilities, bindings, authority/delegation and revocation state.

**Evidence:** field ID, node IDs, enrollment records, registry output.

## CONTRACT C — Real Typed Passage

**Subject:** real consequential inter-node action represented by typed passage.

**PASS:** inspectable/persisted passage reconstructs passage/source/subject/action/target/authority/scope/dependencies/conditions/freshness/lineage/Return plus egress source, ingress target, egress authority basis, ingress correlation and Return correlation as applicable.

**Evidence:** passage ID, runtime artifact, defining source path, correlated trace.

Fixture-only does not pass.

## CONTRACT D — Authority Resolution

**Subject:** current attributable authority.

**PASS:** one valid-standing case succeeds; one otherwise-capable no-standing case fails; controlled egress evaluates current authority; B independently evaluates applicable standing before ingress; current execution authority is rechecked at point of use where separable.

**Evidence:** grant/lineage, authorized case, rejected no-standing case, runtime/test refs.

Capability ≠ Authority.

## CONTRACT E — RIO Admissibility

**Subject:** consequential admissibility.

**PASS:** canonical RIO/admissibility evaluates passage and produces inspectable decision(s) distinct from execution, bound to exact request; bilateral trace distinguishes egress authorization basis and ingress admission judgment even if same canonical service evaluates both contexts.

**Evidence:** passage ID, RIO decision ID(s), artifacts, owner, correlations.

## CONTRACT F — Sentinel / Point-of-Use Fidelity

**Subject:** current authority and fidelity at point of use.

**PASS:** acceptance evidence separately identifies current execution-authority result and fidelity result; changed target plus at least one other material mutation are rejected.

**Evidence:** current-authority record, fidelity result, faithful case, mutation rejections.

## CONTRACT G — Model Aperture

**Subject:** non-authoritative model output.

**PASS:** model output first becomes typed non-authoritative artifact; any model-originated consequential action traverses candidate passage → authority → RIO → Sentinel → execution; direct model-to-consequential-adapter path rejected.

**Evidence:** artifact, type, correlated passage, governed trace, rejection test.

## CONTRACT H — Actual Consequence

**Subject:** real development-safe state change.

**PASS:** real adapter changes a bounded development-safe target and runtime distinguishes requested, authorized, attempted and occurred.

**Evidence:** target, pre-state, invocation, post-state, occurrence.

Mocks/simulation-only fail.

**Subject:** proof lineage and bilateral Return.

**Evidence:** receipt/hash, occurrence ref, passage correlation, Return ID, Return-ingress status, ledger/proof ref.

## CONTRACT J — Revocation and Freshness

**Subject:** invalidation of formerly valid standing and stale/replayed passage.

**PASS:** valid grant permits action; later revocation/expiry rejects materially equivalent action without code change; applicable replay/stale/spent passage rejected.

**Evidence:** grant, first result, invalidation, second result, replay/freshness rejection.

## CONTRACT K — Node Separation

**Subject:** attributable identity and custody separation.

**PASS:** A cannot impersonate B by changing metadata; identities verified; accepted interfaces do not give A unrestricted direct access to B's private runtime merely because both are members.

**Evidence:** node records, identity mechanism, failed impersonation, custody/interface evidence.

## CONTRACT L — Restart / Reconstruction

**Subject:** sufficient persisted continuity after restart.

**PASS:** after stop/restart runtime reconstructs field identity, node identities, active/revoked authority, required bindings, completed passage lineage, receipt and Return correlation without silently substituting new identities.

**Evidence:** pre-state, restart run, post-state, identity comparison, correlation.
