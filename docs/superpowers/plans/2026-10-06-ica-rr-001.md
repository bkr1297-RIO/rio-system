# ICA-RR-001 implementation plan

Spec: `docs/implementation/ica-rr-001/SPEC.md`.

Global constraints: one closed loop; inline implementer; reuse both completed specimens; native authority only; no frozen-file changes; no sensors or autonomous work. Publication to an isolated draft is explicitly authorized by the user. Local dependency integration does not merge the existing PRs.

## Task 1: Runtime journey and attributable register

Produces: `ReferenceWorkspace`, `ICAJourney`, bounded source replay, typed register and view. Consumes: native LocalField/CCM/waist and the two completed specimen APIs.

1. Write prospective lifecycle tests for computed visibility-only change, exact bounded delegation, separate admission/attempt/readback/Return, claim lineage, stale commands and revocation.
2. Run `node --test tests/ica-rr-001/lifecycle.test.mjs`. Expected: missing API assertion fails.
3. Implement source-edge replay and reference native workspace, then the journey owner. Keep capabilities private, export inspectable data only.
4. Run the same tests. Expected: all pass against real SQLite/native artifact effects.
5. Commit runtime and tests; record task completion.

## Task 2: One human surface and negative-space battery

Produces: loopback HTTP host, native-form surface, entry CLI, form-journey tests. Consumes: Task 1 view and bounded dispatch.

1. Write form-driven acceptance and security tests, and UNKNOWN/HOLD/DENY/REVOKE/PARTIAL RETURN tests.
2. Run `node --test tests/ica-rr-001/*.test.mjs`. Expected: missing surface assertion or missing negative behavior fails.
3. Implement one compact surface with all eight lived answers and inspectable lineage, plain controls, request authentication and replay protection. Native HTML works without client scripts.
4. Run the same tests and `npm test`. Expected: all pass. Generate evidence from the actual form paths, not predetermined displayed status strings.
5. Commit surface, tests, scripts and evidence; record completion.

## Task 3: Verify, review and publish evidence

Produces: build report, paired journeys, claim audit, source hashes, executable fixtures and draft PR. Consumes: Task 1 native trace and Task 2 form tests.

1. Run the combined inherited and new suites and schema checks. Expected: zero unreported failures/skips. Compile the existing nominal type consumer using TS 5.9.3.
2. Run a fresh read-only whole-branch review. Review focus: controller identity qualification, forged/stale requests, duplicate effects, misleading claims after revocation, raw data ingress, UNKNOWN versus successful receipt, reporting completeness versus objective, fixture disclosure, reentry continuity, no authority on GET or radar refresh. No parallel implementer.
3. Fix Important/Critical findings once with RED→GREEN regressions and the full suite. Record rulings and deferred minors.
4. Publish an isolated draft using authorized GitHub tools; disclose exact source trees and dependency lineage. Do not merge predecessor PRs.
5. Expected: verified local tree equals published tree; evidence and known gaps are linked in a self-contained report.
